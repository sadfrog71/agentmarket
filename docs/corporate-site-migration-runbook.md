# 企业官网迁移运行手册

本手册约束企业官网内容迁移的源封存、升级前置检查、隔离演练和流量级回滚。它不授权执行生产数据库变更、部署或切流；每个生产动作仍须由已授权的 DBA、运维和发布负责人在变更窗口内执行。

## 1. 适用范围与停止条件

适用对象为获授权的官网导出包，以及智能体市场仓库中的官网升级 SQL。静态官网导出包是迁移依据和旧站回滚参考，不是上线后的第二个可编辑内容源。

出现以下任一情况时，停止后续迁移或切流，保留现场和报告，不以人工修改源文件绕过检查：

- manifest 的未分类文件数不为 0，或固定页面、新闻、资质 / 专利 PDF 基线不符合确认值；
- 源快照哈希、候选升级 SQL 哈希或升级编号与预检报告不一致；
- 备份不能恢复至隔离副本，或隔离演练改变了市场功能、结构或数据基线；
- 内容、媒体、旧路径或市场基线验证存在未获批准的差异。

## 2. 源封存与 manifest

1. 内容负责人确认一份官网导出包作为本次迁移源，并记录其取得时间、提供方和授权范围。源目录在迁移窗口内保持只读；不得继续在其中修订页面、图片、证书或新闻。
2. 在受控工作副本中，使用 `build_manifest.py` 对该导出包生成 JSON manifest 和 Markdown 清单。工具只读取源目录，输出中的 `legacy_path` 均相对来源根目录，不包含本机绝对路径。
3. 核对 manifest 的 `snapshot_sha256`、文件总数和分类结果。当前获授权基线为 29 个固定页面、53 篇新闻文章、71 份资质 / 专利 PDF，且所有文件必须属于 `IMPORT`、`ARCHIVE` 或 `APPROVED_EXCLUSION` 之一。
4. 将 manifest、内容清单、官网导出包校验记录和来源授权信息一起归档。`ARCHIVE` 和 `APPROVED_EXCLUSION` 只在获得明确批准后保持该状态；不得静默忽略文件。
5. 源封存后发现静态内容变化时，不覆盖既有 manifest。重新取得导出包并生成新的 delta manifest，说明新增、删除和哈希变化后再进入下一次演练。

## 3. 升级前置检查

官网升级仅能以新增、可审计的 SQL 文件进入已有数据库。升级文件应遵守以下前提：

- 文件名使用 `marketplace-upgrade-NNN-*.sql`，编号从现有最高连续编号的下一个编号开始；不得复用、插入或覆盖既有编号。
- 升级以新增表、索引、约束、字典或数据为主。不得删除、重命名、收缩或重建既有市场对象，不得依赖删除数据卷或重新初始化数据库。
- 候选 SQL 必须是扫描到的连续编号末尾，并保持可重复执行所需的存在性检查、唯一约束或升级登记策略。
- 使用 `upgrade_preflight.py` 生成只读 JSON 报告。报告必须显示连续编号通过、候选 SQL 的 SHA-256 已记录、`database_interaction` 为 `none`，并且 `ok` 为 `true`。

预检工具仅读取本地 SQL 文件。它不读取数据库凭据、不连接数据库、不执行 SQL。预检报告用于与隔离演练和生产变更单中的脚本哈希比对，不能替代真实的升级登记、结构验证或备份恢复验证。

## 4. 生产备份—恢复隔离演练

生产切流前，DBA 和运维人员须完成一次从生产备份恢复出的隔离副本演练。隔离副本不得承接生产流量，不得回写生产数据库、上传卷或公网入口。

演练记录至少包括：

- 备份标识、恢复开始和完成时间、恢复校验结果，以及可接受的 RPO / RTO 结论；
- 使用的代码版本、manifest 快照哈希、候选 SQL 路径和 SHA-256、预检报告；
- 已应用升级账本、官网表 / 索引预期，以及升级前后市场表结构和行数基线；
- 在隔离副本上的升级、媒体暂存、内容导入、来源闭包、引用闭包、公开闭包和市场冒烟检查结果；
- 执行人、复核人、失败项、处理结论和是否允许进入生产窗口。

演练失败时，只能在隔离副本中定位并修正代码、SQL 或迁移资料。修正后的源或 SQL 会改变哈希，须重新运行源 manifest 或升级预检，并重新完成适用范围内的演练。

## 5. 生产窗口门槛

进入生产窗口前，应由内容负责人、DBA、运维和发布负责人共同确认：

- 冻结 manifest 与拟导入内容一致，差异为零或已有逐项批准；
- 备份恢复演练已通过，候选 SQL 与预检报告哈希一致；
- 市场前台、后台、接口和数据基线检查通过，官网新入口尚未承接正式流量；
- 旧静态站构件、旧路由配置和回切开关可用；
- 生产监控、日志、责任人和停止条件已记录。

生产升级、导入和切流的实际执行步骤应引用经批准的变更单和当期运维方案。本手册不提供会修改生产环境的命令。

## 6. 默认回滚：入口流量级回滚

默认回滚边界是官网入口流量，而不是共享数据库。发生官网首页、公开 API、代表媒体连续失败，任一必需旧路径 / 媒体不可用，或任一市场冒烟检查失败时：

1. 停止将官网流量导入新入口，并恢复旧静态官网的已验证路由。
2. 固定或下线新官网服务的公网入口，保留日志、manifest、预检报告和失败证据。
3. 保留新增官网表、媒体副本、导入运行记录和审计记录，不删除数据，不以整库恢复作为默认动作。
4. 复核旧站和市场健康状态，记录回滚时间、触发条件、影响范围和后续修复项。

仅当 DBA 根据明确的 RPO / PITR 评估确认共享数据库恢复不会覆盖市场写入时，才可单独决定整库恢复。该决定不属于官网流量级回滚的默认范围。

## 7. 记录与交接

每次演练、生产预装、切流或回滚都应关联以下不可变标识：代码版本、源快照 SHA-256、manifest 版本、候选 SQL SHA-256、预检报告、备份标识、执行记录和验证结论。未形成这些记录时，状态只能标记为「未完成验证」，不能标记为迁移完成或上线验收通过。
